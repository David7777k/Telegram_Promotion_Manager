## E0 — первый коммит и проверка

1. Найти действующий CPython. На машине аудита работал прямой путь, указанный в статусе, а aliases из WindowsApps не запускались. Выбрать один интерпретатор для воспроизводимого Windows-build, сначала проверить доступность wheels и запуска Qt. Проверить версию SQLite из выбранного бинарника.
2. Сделать исходную резервную копию v2 и записать SHA-256 оригиналов; в этой папке Git-метаданные не обнаружены. Копия исходников и копия пользовательских данных — разные операции. Прежде чем открывать данные на запись в E1, сохранить исходные JSON защищённым способом. Использовать синтетические фикстуры вместо реальной рекламной истории.
3. Запустить 12 legacy-тестов из чистого окружения. Добавить характеристические тесты вокруг текущих контрактов v1/v2, не фиксируя известные дефекты как требования. Не удалять v2 entry points.
4. Ввести pyproject и минимальный пакет с отдельным smoke entry point, каталог тестов и временный профиль. Без реального dispatch. Закрепить команды pytest/legacy unittest и версию сборочной среды. После E0 можно отдельно брать хранение, домен и UI.

## Тестирование

| Слой | Набор проверок |
|---|---|
| Unit | Legacy fields/types, нормализация username/invite, DST gap/fold и UTC, согласия, ссылки, price+period, Spintax, обрезка/экранирование, классификация Telegram ошибок, источники метрик и формулы. |
| SQLite integration | Создание/обновление схемы, отчёт импорта, второй экземпляр, транзакционный rollback, lease CAS, уникальность scope/alias/слота, повтор после сбоя, резервная копия и restore, перенос между Windows-профилями с недоступным ciphertext. |
| Telegram adapter | Fake HTTP и MTProto: success, 400/401/403/429/5xx, retry_after отсутствует, migrate_to_chat_id, malformed success, timeout, отзыв прав, форумная тема, media+button, 2FA, QR TTL, отмена, join request. Отдельные opt-in проверки только на собственном или специально разрешённом тестовом чате. |
| Crash matrix | Процесс завершается до claim, после claim, после intent, после принятия API, после commit. Проверить SQL, результат UI, количество внешних вызовов, cooldown и видимость в журнале. Повторить для create paid link и receipt. |
| UI | Старт пустого/импортированного профиля, мастер, демо, подключение/отказ, синхронизация, импорт, создание кампании, рендер, расписание, отмена, права, 429, перезапуск, аналитика, экспорт, завершение. 100/125/150% DPI и клавиатура, smoke на Windows с кириллицей в пути. |
| Упаковка | PyInstaller x64, Qt plugins/resources, TZ data, иконка, чистый Windows-профиль без Python, запуск обеими привычными точками входа, обновление и откат. Проверить открытие SQLite/DPAPI вне дерева установки. |

CI по умолчанию офлайн для Telegram. Поддельные клиенты не должны уметь выйти в интернет. Живые credentials не попадают в fixtures, скриншоты, CI artifacts или дистрибутив. Результат по каждому сценарию отмечать как «пройден», «не пройден» или «не проверен» с причиной. Старые тесты удалять только при полном переносе покрытия и переключении точки входа.

Граница завершения P0 — в отдельном демо-профиле пользователь собирает кампанию, подтверждает точный предпросмотр и видит симуляцию очереди; для режима live все операции идут через проверенный Bot API адаптер с сохранением исходов. Граница 3.0 — мастер, поиск, календарь, отчёты и воспроизводимая Windows-поставка прошли соответствующую проверку. Ссылки на конкретные задачи и критерии — в [TASKS.md](TASKS.md).
